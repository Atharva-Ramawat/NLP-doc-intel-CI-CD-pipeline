# Production-Grade Document Intelligence Pipeline

This repository contains the infrastructure and deployment configurations for an event-driven Document Intelligence Pipeline. The system is designed to ingest documents, manage them via an asynchronous message queue, perform Natural Language Processing (NLP) summarization and extraction, and store the results persistently.

The project utilizes a microservices architecture deployed on Kubernetes, managed entirely through a GitOps continuous delivery workflow.

---

## System Architecture

The application is broken down into highly decoupled services to ensure scalability, fault tolerance, and clear separation of concerns.

### Ingestion API (FastAPI)
Acts as the primary entry point. It receives document uploads, validates the data, and orchestrates the initial storage and queuing.

### Object Storage (MinIO)
An S3-compatible storage layer used to securely store the raw uploaded documents (e.g., text, PDF) before processing.

### Message Broker (Redis)
Handles asynchronous task queuing. Once a document is saved to MinIO, a job ticket is pushed to Redis to be consumed by the NLP engine.

### Processing Engine (NLP Worker)
A background service that continuously polls Redis for new jobs, retrieves the corresponding document from MinIO, runs the NLP extraction/summarization logic, and outputs the final data.

### Relational Database (PostgreSQL)
Stores the final structured metadata, extracted text, and summaries generated by the NLP worker.

## Continuous Integration & Delivery (CI/CD) Workflow

This project enforces a strict **Shift-Left Security and Quality Pipeline**.

### 1. Code Commit
Developers push application logic to the source code repository.

### 2. Build & Test (Jenkins)
Jenkins triggers a build pipeline, installing dependencies via `pipenv` and running unit tests via `pytest`.

### 3. Quality Gate (SonarQube)
The code undergoes static analysis to enforce coverage and code quality standards.

### 4. Security Scan (Trivy)
The container image is built and scanned for critical vulnerabilities before being authorized for the registry.

### 5. Image Registry
Upon passing all quality and security gates, the image is pushed to Docker Hub.

### 6. GitOps Synchronization (Argo CD)
Argo CD monitors this configuration repository. When image tags or Kubernetes manifests are updated, Argo CD automatically synchronizes the cluster state to match the repository.

## Kubernetes Infrastructure

All infrastructure definitions are located in the `k8s/` directory and are declarative.

### Deployments
Manages the lifecycle of the FastAPI application, NLP Worker, and stateful services.

### Services
Provides internal DNS resolution and load balancing between pods.

### Ingress
Exposes the FastAPI endpoints and Grafana dashboards to external traffic using path-based routing.

### Autoscaling
The `hpa-worker.yaml` manifest ensures NLP workers scale horizontally based on CPU utilization to handle high document throughput.

## Local Deployment Instructions

While Argo CD manages the production state, the cluster can be deployed manually for development and testing.

### Prerequisites

- Kubernetes Cluster
- kubectl
- Docker

### Deploy the Application

```bash
kubectl apply -f k8s/
```

### Verify Deployment

```bash
kubectl get pods -n default
```

Ensure all pods transition to the `Running` state.

### Access API Documentation

Open:

```text
http://<INGRESS-IP>/docs
```

## Monitoring and Observability

The observability stack runs in the `monitoring` namespace. Prometheus is configured to scrape metrics from cluster nodes and application pods.

### Access Grafana Locally

```bash
kubectl port-forward svc/observability-stack-grafana 3000:80 -n monitoring
```

Open:

```text
http://localhost:3000
```

The dashboards provide:

- Application latency metrics
- Request throughput
- Pod resource utilization
- Cluster health monitoring
- Infrastructure performance metrics
